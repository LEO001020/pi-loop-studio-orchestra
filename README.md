# Orchestra

**Pi Loop Studio / Orchestra** 是一个 Windows 原生、证据驱动、可恢复的并行 Pi Agent Loop。项目的规范开源名称为 **`pi-loop-studio/orchestra`**。这是独立实现，不是旧 Pi Web 的换皮或在旧目录继续打补丁。源码复用了已审读的独立 `pi-loop-v2` 参考实现的一部分，再修正其调度、恢复、工具、发布、UI 与安装问题；并非声称所有代码都从零编写。

## 开始使用

在本目录双击 **`Open Pi Loop Studio.cmd`**，或使用安装器创建的桌面快捷方式。启动器使用项目私有 Node，在 Microsoft Edge 应用窗口打开 UI；未找到 Edge 时打开默认浏览器。默认地址是 **`http://127.0.0.1:3320`**，可在设置中修改。不需要打开或控制开发者工具，也不需要安装 Windows 服务。

首次安装、移动目录或从便携包解压后，先双击 **`Install Pi Loop Studio.cmd`**。安装器使用随附运行时修正 Python 路径与入口脚本、验证 Git、检查 TypeScript 并构建 UI。完整便携包已包含 Node、Python、Git 与 node_modules；缺失依赖时安装器才按 package-lock.json 下载。安装器不会修改防火墙、AppContainer、账户权限、MCP 或模型代理。

便携发布包和源码仓库**不包含 `.local` 凭据、私人会话或用户工作区**。安装后，在“设置与模型 → 模型连接”中填写三个席位的 API Key。密钥字段留空表示保留现有值，服务器不向 UI 返回保存后的密钥。不要把本机 `.local` 文件夹公开上传。

关闭应用窗口不会取消任务；任务属于本地服务。**`Stop Pi Loop Studio.cmd`** 关闭本应用服务并保留恢复状态，不停止 8045 代理或 coding MCP。重复打开启动器会连接已运行的同目录服务。

## 发出一个任务

点击“新建对话”，从顶部路径选择具体项目，输入目标与验收条件。允许的工作区根目录及别名可在设置中调整。请选择真正的项目子目录，不要把整块磁盘、源码集合根目录或包含 Orchestra 本身的父目录作为任务目标。

发送前可设置该任务的**唯一 token 预算**及岗位预设。自动模式把问候与普通问答交给快速席位；研究、检查文件、写代码等任务必须进入完整图。选择“强制任务流程”可避免意图分类歧义；“纯对话”不会声称修改了本地文件。

任务图为：

```text
识别意图 → 工作区快照 → 主席位实际侦查与派发
  → 并行侦查 → 独立证据审核 → 主席位任务 DAG
  → 各岗位 [执行 → 独立审核 → 宿主整合 / 返工]
  → 实际命令验证 → 主席位仲裁 → 校验基线并发布

审核多轮失败 → 携带失败证据重新规划；不降低原始验收条件
预算阈值 / 用户暂停 → 保留检查点 → 调整后继续
错误 → 明确阻塞；取消 → 终止当前运行
```

执行者只写自己的工作树与分配路径；审核者读取固定提案的另一个副本。未经审核的前置产物不会传给下游。用户目录只由宿主发布过程写入。图、岗位、提案差异、真实账单、命令 stdout/stderr/exit code 均可在右侧工作台查看和导出；图事件支持分页回放。

## 预算和岗位

预算是**累计真实 token 用量的停止新增请求阈值**，不是货币金额，也不是事前不可能超额的硬上限。没有预算请求、预留、角色押金或冻结。已经发出的请求继续返回并结算，因此可能超额；界面明确显示超额。未收到 usage 时标记未知，不将其视为零费用，也不伪造提供方账单。

主席位为单实例；每任务可配置 1–20 个执行席位和 1–8 个辅助席位，并为三个角色分别选择兼容端点与模型。执行岗位可配置名称、职责与人数，保存为预设后在发送前一键应用，例如“5 实现 + 5 测试 + 2 研究，4 辅助”。各执行岗位人数合计必须等于该任务的执行席位数。全宿主还设有 1/20/8 的并发上界，防止不同工作区同时运行时突破既定模型矩阵。

辅助席位用于意图选择、快速对话和独立审核。执行岗位配额在执行阶段占用，等待辅助审核不继续霸占执行岗位。依赖就绪即派发，不等整批任务全部结束才开启下一批。真实依赖不足十个时不复制无意义任务凑数字；是否实际达到十路，以请求时间区间回执为准。

## 可视化设置

UI 提供预算、三席位的模型/协议/基址/凭据/推理级别/上下文/输出长度/并发/超时、执行岗位与预设、工作区根目录和别名、检索服务、来源大小、返工与工具轮数、Python 与命令超时、快照限制、验证命令、主题、上下文压缩和恢复开关。端口变更需重启服务；其他设置对新任务生效，运行中的预算可直接调整。

模型 ID、上下文上限与推理级别是用户端点的配置事实，不代表已经独立验证提供方标称的全部模型能力。没有在启动时自动升级模型或依赖。

## 恢复与边界

candidate.3 修复了原生单元未知副作用继续执行、Node 借用宿主未声明依赖、正常构建输出误拒等反例；另增加只读归档源码分页入口，避免压缩乱码污染推理。修复前／后的具体证据及边界见 `docs/CANDIDATE-3.md`。

“设置与模型 → 运行与恢复 → 可再生构建输出目录”可配置 `dist` 等新生成目录。该设置只将新建且未分配为交付物的产物作为临时构建输出；已有文件的变动仍会使验证失败，不能把整个 src 目录豁免。项目使用 `npm ci` 安装自己的依赖，不能再误用 Pi 宿主的 node_modules。

会话 ID、消息、任务图快照、请求用量与岗位检查点持久化到 SQLite。断网、刷新或关闭标签页不会删除会话。重启后恢复未完成节点；完成节点使用已有检查点。结果未知的 PowerShell/Python 操作不会被无提示重放，需在回执中检查并明确允许重试。这样的确认针对已知未知副作用，不是每步请求授权。

归档不会删除对话。左侧勾选“显示归档会话”即可重新打开历史记录；顶部“恢复会话”可取消归档。已归档的验证任务也能查看原始任务图、岗位、差异和命令回执。

Python 仅在岗位调用时启动，JSON-lines 全程 UTF-8，内核状态在该岗位生命周期内保留。普通 pip install 默认写入岗位 `.pi-deps`；npm 全局安装默认写入岗位 `.pi-npm-prefix`，而非共享运行时。它们是防止正常协作误写的工程默认值，**不是 OS 安全沙箱**。任意 PowerShell/Python 仍拥有当前用户权限，能够故意越过约定；不要把不可信恶意代码当作已隔离执行。

发布使用内容哈希检查、备份和逐文件日志，不宣称多文件原子事务。用户在任务期间改写原始目录时会阻塞发布，避免把旧基线的测试结果归给新的目录状态。中途磁盘故障可能留下部分已写文件，需查看该任务的 `publication.json`。

## 目录与验收

`server/`：Pi 接入、XState 图、SQLite、原生工具与工作树；`ui/`：assistant-ui、React Flow 工作台；`vendor/pi-repl-py/`：保留并修正的 Python 桥；`.runtime/`、`.python/`、`node_modules/`：随附运行依赖；`.local/`：私密状态；`workspace/`：任务目录；`validation/`：包含失败在内的本轮回执；`docs/`：架构、来源与交付证据。

最终验收状态以 **`VERIFICATION.md`**、**`BLOCKED-UNVERIFIED.md`** 和 **`docs/verification/acceptance.json`** 为准。代码存在、进程启动或一组测试通过都不等于所有功能验证完成。历史 rc.5/rc.7 的验证不为本轮新功能背书。

```bat
.runtime\node-home\node.exe scripts\doctor.mjs
.runtime\node-home\node.exe --test tests\core.test.mjs tests\workflow.test.mjs tests\http.test.mjs tests\transport.test.mjs
.runtime\node-home\node.exe scripts\ui-acceptance.mjs
.runtime\node-home\node.exe scripts\live-probe.mjs
.runtime\node-home\node.exe scripts\live-acceptance.mjs --run <run-id>
.runtime\node-home\node.exe scripts\accept-release-20260911.mjs --run <run-id>
.runtime\node-home\node.exe scripts\release.mjs --verify
```

解压后安装前使用 `release.mjs --verify` 核对全部字节。安装会重建 Python 的绝对路径入口；安装后可使用 `release.mjs --verify --installed`，它明确列出迁移入口的校验例外，仍核验其余源码和运行依赖。实际压缩包的解压安装回执位于原交付目录 `release/ARCHIVE-VERIFICATION.json`。

真实模型探针和 UI 对话测试会消耗已配置服务额度。`live-acceptance --run` 读取指定既有任务并复测产物，不重新提交；不带 `--run` 则会创建新任务。只读模型阶段的短暂网络故障在图中有限重试，已经完成的侦查不重做，未知账单不消失。错误可查看 `.local/server.stderr.log` 与任务导出回执。不要通过删除 `.local`“修复”问题。
