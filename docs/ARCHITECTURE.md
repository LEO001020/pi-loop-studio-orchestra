# 约束内的架构裁决

## 判定与证据

本轮目标是可验证任务成功率、可恢复性和用户可用性，不是代理数量或代码数量。采用的方案是：**Pi 原生工具循环 + 单主协调、独立审核门控的 DAG + XState 持久状态 + assistant-ui / React Flow 桌面工作台**。它是在已审读的证据、本机运行条件和既定异构模型矩阵下选出的 production candidate；没有证明全局最优，也没有对未部署的替代方案伪造性能基准。

证据分三层：实际 Windows 命令与模型回执决定本机可运行范围；锁定 npm 包源码与类型声明决定 API；论文决定优先探索的机制，而不决定安装版本接口。来源原文、时间、HTTP 状态和哈希保存在 `docs/evidence/audit-1789082112111/`；共 25 个公开来源的采集不是“25 篇完整论文复现”。本报告的研究结论限定在实际阅读支持的范围。网页文档可能已滚动到新大版本，生产代码以 package-lock 和安装版本为准。

## 搜索空间及取舍

| 维度 | 审查的候选 | 采用 / 未采用的具体理由 |
|---|---|---|
| Pi 执行核心 | pi-agent-core、完整 AgentSession、pi-subagents | 采用 Pi Agent 与原生 read/write/edit/PowerShell 工具；上下文摘要也复用 Pi。pi-subagents 是首选参考，其默认派发仍由父模型选择，自动 reviewer 并非安装即启用；本任务要求宿主强制派发、固定提案和用量统一持久化，因此不叠加第二套子代理生命周期。它不是因为“功能差”被否决。 |

## 研究机制，不是装饰性引文

ReAct（2210.03629）提供动作—观察进入后续推理的机制参照，因此不把一次文本生成冒充执行。Reflexion（2303.11366）与 Self-Refine（2303.17651）支持研究反馈后修订，但自我认可不能替代独立审计。Agentless（2407.01489）与 SWE-agent（2405.15793）分别提示分阶段验证和 agent—computer interface 的重要性；本轮复用成熟工具接口，减少自造 shell 协议。

MAST（2503.13657）将多 agent 失败区分为系统设计、agent 间失配、验证与终止问题。这个分类直接对应本轮的显式任务契约、文件所有权与审核/终验门控，而非“再加一个 reviewer 就能消灭错误”。《Towards a Science of Scaling Agent Systems》（2512.08296）在受控任务中观察到拓扑与任务可并行性相关，协调也有开销。由此作出的**工程推论**是减少未经核验的自由传播，并让真实依赖决定调度；论文中的收益数字不能移植为 GLM/Gemini 这组端点的成功率。

Agent Workflow Memory（2409.07429）的研究方向有助于区分可复用流程知识与本次执行状态，但本轮没有额外引入向量数据库或宣称实现了该论文全部机制。会话消息、已完成任务索引和原始来源分页已经满足当前连续性底线。需要更大规模语义检索时，应另做实际任务基准，而不是把更多组件当成改进证据。

## 调度与错误传播的实现

根流程由 XState 运行，不依赖模型愿不愿意调用子代理。principal 先读取工作区并提供不同焦点的侦查分配，执行层并行读取证据，辅助模型独立核对，只有通过的报告交给规划。规划必须生成无环 dependsOn 图、有效岗位与文件所有权；无依赖任务不允许重叠写同一文件或目录。

执行岗位只在实际工作时占岗位配额；进入辅助审核后释放该配额。宿主按依赖就绪动态补位，不用整批 Promise 完成作为下一批开工的全局栅栏。辅助审核读取另一个副本，并绑定提案的内容清单；审核期间改变源文件不能把修补后的测试成绩归给原提案。审核多次拒绝进入 principal 重规划，最初验收标准保持不变，失败任务保留历史并标记被后续轮次替代。

Git 存储以实际文件字节建立对象，不执行仓库的 clean/smudge 转换来“重建”产物。候选整合与发布使用内容哈希。最终验证在候选副本执行命令；源文件新增、删除、修改都算变动。被验证清单与发布清单绑定，原始工作区里即便不是此次修改的依赖文件变了，也不能沿用旧测试发布。

## 恢复与非原子性

只读模型阶段的短暂网络断连、流被终止、限流和请求超时可进入显式 recovering 状态，在 UI 现有返工上限内有限重试。它只重试未完成的节点，已审核侦查继续使用持久检查点；未知调用成本仍显示未知。执行 PowerShell/Python 的未知副作用不走这条自动重试边。提供方超时和用户取消分别为 MODEL_TIMEOUT 与 CANCELLED，不再把网络超时当成永久取消任务。

XState 官方文档明确：恢复快照不会重跑普通 action，但进行中的 invocation 会重新启动。故 SQLite 中额外持久化完成检查点，原生命令预先留下 effect 回执；未知结果不静默重放。这里的回执是副作用语义，不是旧式看门狗链。不能由“持久图”推导对 HTTP 或 shell 外部副作用的 exactly-once。

发送请求带幂等 ID，服务在同一事务创建任务和用户消息。失去 HTTP 响应后重发同一内容不会创建重复运行；同一 ID 配不同内容报冲突。失效 session 直接给可见错误并回到可用新会话。SSE backlog 超出预览范围时要求重新读取物化状态，完整图事件仍可分页导出。

发布是带备份和逐文件日志的可恢复序列，并非多文件原子事务。任何已经部分写入的状态必须从 publication.json 可见。工作树/默认依赖目录无法阻止恶意代码的绝对路径访问，OS 沙箱、多人远程部署与跨机恢复不在本轮实现范围。

## 实证边界

本轮已完成十模块数值库真实任务：428 次请求、4,205,068 token、12/12 岗位审核整合、106 个 Node 测试通过，并已发布；耗时约 50 分钟，明显包含高推理配置、侦查/审核成本与人工暂停恢复，不能宣称低延迟或成本最优。并发峰值必须从成功返回请求的发起/完成时间与实际 dispatch 记录计算，不靠配置值或 Promise 数。

当前最终源码的新任务回归、预算探针、UI、基础环境、依赖隔离及便携安装的状态由 `../VERIFICATION.md` 自动汇总。单个或少数任务通过不证明复杂仓库的总体成功率，更不替代用户真实使用评价。未验证项不因“候选”标签而消失。

第二个真实任务在提供方连接中断后使用同一 ID 跨宿主重启恢复。已完成的侦查是旧运行阶段的检查点，后续执行与审核由修正后的宿主继续；不能把这条证据描述为同一源码版本从头无中断运行。其真实用量如存在未知项，报告仅表示已报告 token 的小计，不是完整计费总额。
